**Version:** 1.0

---

# 1. Introduction

## 1.1 Purpose

This document defines the complete software architecture of Constella.

Its purpose is to eliminate ambiguity during development by defining:

* System architecture
* Core entities
* User flow
* Screen flow
* Storage architecture
* Database structure
* Search architecture
* AI architecture
* Synchronization architecture
* Component architecture

This document is written for developers and AI coding agents.

Every implementation decision should follow this specification.

---

# 1.2 What is Constella?

Constella is a **Local-First, Space-Based Personal Knowledge Operating System**.

Users create **Spaces** for meaningful topics in their lives.

Examples

* React
* Machine Learning
* SpendMap
* Dream House
* Photography
* Startup
* Fitness

Instead of storing scattered notes, screenshots, links and code snippets, every piece of information becomes part of its corresponding Space.

A Space continuously evolves as users learn, build and organize.

---

# 1.3 Primary Objectives

The system must achieve the following objectives.

• Organize knowledge around Spaces instead of files.

• Work completely offline.

• Synchronize using user-owned cloud storage.

• Support long-term knowledge growth.

• Connect related knowledge.

• Make every piece of information searchable.

• Never lose user data.

• Scale to tens of thousands of Artifacts.

# 4. Universe

## Description

Universe is the root container.

Each user owns exactly one Universe.

The Universe contains every Space created by the user.

The Universe itself contains no knowledge.

It only organizes Spaces.

---

## Responsibilities

Maintain Space Registry.

Maintain Global Search Index.

Maintain Global Timeline.

Maintain Storage Configuration.

Maintain User Preferences.

Maintain Global Relationships.

---

## Constraints

Only one Universe per user.

Cannot be deleted accidentally.

Contains unlimited Spaces.

# 15. Database Architecture

## Overview

Constella uses a **Local-First Database**.

The local database is the single source of truth.

Cloud storage is **never queried directly** by the application.

Every operation reads and writes to the local database.

Cloud providers only receive synchronized copies.

Recommended Technologies

SQLite

Web

IndexedDB (Dexie)

# 59. Development Principles

Every feature added to Constella must satisfy these rules.

1. Every Artifact belongs to one Space.

2. Every modification saves automatically.

3. Every Artifact is searchable.

4. Every Artifact supports relationships.

5. The local database is always the source of truth.

6. Cloud providers are synchronization targets only.

7. UI never communicates directly with storage providers.

8. UI never communicates directly with the database.

9. Business logic belongs to repositories and services.

10. Search must remain functional offline.

11. AI never modifies user data automatically.

12. Synchronization must never block the user.

13. Users always own their data.

14. New features should extend the existing architecture rather than introduce parallel systems.

15. Simplicity takes priority over feature count.

# 61. Final Architecture Summary

Constella follows a **Local-First, Space-Centric architecture**.

The application is built around four core entities:

```
Universe
    ↓
Spaces
    ↓
Artifacts
    ↓
Blocks
```

Every user action follows the same lifecycle:

```
User Action
    ↓
Update Local Database
    ↓
Update Search Index
    ↓
Update Relationships
    ↓
Refresh UI
    ↓
Queue Synchronization
    ↓
Background Sync to BYOS Provider
```

The application never depends on cloud availability for normal operation.

Knowledge is always created, stored and accessed locally first.

Cloud providers are responsible only for synchronization and backup through the Storage Engine.

This architecture ensures:

* Fast local performance
* Offline functionality
* User ownership of data
* Provider independence
* Scalable knowledge organization
* Clear separation of concerns
* Maintainable codebase
* Extensible feature development

This document defines the baseline architecture for Constella v1.0. All future development should extend this architecture rather than replace its core principles.
